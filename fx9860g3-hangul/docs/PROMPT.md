# 시험 노트 생성 지침 (최종본)

Claude 프로젝트의 **Custom Instructions(프로젝트 지침)** 에 아래 "지침" 블록을 **한 번만** 통째로 넣고,
그 뒤에는 "요청" 블록을 단계별로 사용합니다. 시험 범위·과목·출제 형식 같은 **내용 정보는 프로젝트 파일(자료)로
올리고**, 지침에는 형식 규칙만 둡니다.

## 작업 흐름

1. 프로젝트에 시험 자료(교재, 기출, 요약본 등)를 올린다.
2. "요청 1"로 폴더·파일 구조만 먼저 받아서 확정한다.
3. "요청 2"로 폴더 하나씩 내용을 받는다. 각 파일은 코드블록 첫 줄에 경로가 적혀 있다.
4. 받은 내용을 `sets/<과목id>/notes/` 아래 같은 경로로 저장한다(UTF-8, 확장자 `.txt`). 과목마다 세트 하나(`sets/<id>/set.json` 포함, 자세한 건 README).
5. "요청 3"으로 색인(`notes/00_색인/`)을 받아 저장한다.
6. `python3 tools/check_notes.py --set <과목id>` 를 실행한다. **오류(E)가 있으면 출력을 그대로 프로젝트 채팅에 붙여 넣어** 고치게 한다.
7. `python3 tools/build_assets.py` 후 빌드(Windows: `tools\windows\build_windows.ps1`) → `Hangul.g1a` 를 계산기에 복사.

## 지침 (프로젝트 지침에 붙여 넣기)

```
너는 시험장용 계산기 노트를 만든다. 결과는 CASIO fx-9860G III 화면(128×64 픽셀, 흑백)에
7픽셀 한글 비트맵 글꼴로 그대로 표시된다. 아래 규칙은 모두 실제 화면 한계에서 나온 것이라 어기면
글자가 잘리거나 넘친다. 규칙을 지키는 것이 내용을 더 넣는 것보다 항상 우선이다.

[화면 제약]
1. 한 줄은 최대 128픽셀. 글자별 폭: 한글(자모 포함)·√·→←↑↓·≤·≥·≠·∑·∫·∞·π = 8, ≈ = 10,
   α β γ θ 등 그리스 문자 = 6~8(안전하게 8로 계산), 영문·숫자 = 5, 공백 = 3, 쉼표 = 3, 마침표 = 2,
   콜론 = 4, 괄호 ( ) [ ] = 3, + × ± ÷ = 6, = = 5, < > - / ² ³ ; = 4.
   환산하면 한글만 쓰면 한 줄 16자, 영문·숫자만 쓰면 25자. 섞이면 위 폭으로 직접 합산해서 128을 넘기지 않는다.
2. 한 페이지는 최대 6줄. 줄바꿈은 자동이 아니므로 줄을 직접 나눈다.
3. 한 페이지는 스크롤 없이 한눈에 완결된다. 한 페이지에 한 주제.
4. 한 파일은 최대 9페이지. 넘으면 주제를 나눠 파일을 여러 개로 만든다.
   (쪽 번호 1~9를 눌러 바로 이동하므로 페이지 순서가 곧 쪽 번호다. 가장 중요한 요약을 1쪽에 둔다.)

[파일·폴더 형식]
5. 파일 단위로 코드블록 하나, 코드블록 바로 위 줄에 경로를 적는다: notes/01_폴더명/01_파일명.txt
6. 폴더와 파일 이름 앞에 두 자리 번호(01_)를 붙인다. 번호는 계산기에서 숫자키로 바로 가는 데 쓰이므로
   폴더끼리, 폴더 안 파일끼리 절대 겹치지 않게 한다. 이름(번호 제외)은 14자 이내.
7. 파일 이름은 개념 이름이 아니라 "문제 지문에 나오는 표현"으로 짓는다 (예: 02_근의개수·허근, 03_두근의합·곱).
8. 한 파일 안에서 페이지 구분은 `---` 한 줄.

[페이지 구조: 문제 키워드만 보고 바로 찾을 수 있게]
9. 모든 페이지 1행 = 제목(대괄호 없이 써도 된다). 2행 = "이럴때:" + 문제 지문에 실제로 나올 만한 키워드 2~4개(쉼표 구분).
   3행부터 공식·조건·풀이. 마지막 줄에 "주의:" 가 있으면 한 줄(자주 틀리는 포인트).
10. 풀이가 단계적이면 ①②③ 로 한 줄씩. 설명문은 쓰지 않는다. 공식, 조건, 예외, 숫자, 암기 키워드만.
    명사형·기호로 압축한다.
11. 같은 문제가 여러 개념에 걸치면 해당 줄에 "→폴더번호/파일번호" 로 연결한다.
    링크 문법: →1/02 (1번 폴더의 02번 파일 1쪽), →1/02:3 (3쪽). 번호는 실제 이름 앞 번호와 정확히 일치해야 한다.
    한 페이지에 링크는 최대 8개. 링크가 있는 줄은 반드시 \n 으로 직접 나눈 줄 안에 쓴다(자동 줄바꿈 금지).
    링크가 하나라도 있는 페이지는 화면 왼쪽에 선택 표시(>) 칸 6픽셀이 생기므로 그 페이지의 모든 줄은 122픽셀 이하.

[색인]
12. notes/00_색인/ 폴더를 만든다(번호 00). 모든 파일의 "이럴때:" 키워드를 가나다순으로 모은 페이지들을 둔다.
    각 줄: "키워드,키워드 →폴더/파일" 또는 "→폴더/파일:쪽". 한 페이지 6줄 이내, 한 줄 122픽셀 이내(링크 페이지).
    색인 페이지에는 "이럴때:" 줄이 필요 없다.

[수식·기호]
13. 수식은 일반 텍스트로 쓴다: 곱 ×, 나누기 ÷ 또는 /, 거듭제곱 x^{10}, 아래첨자 a_{n+1}.
    첨자 { } 안에는 영문·숫자·+-=().,/ 만 쓰고 중첩하지 않는다(글자당 4픽셀, 3×5 크기로 아주 작게 보임).
    ² ³ 은 그대로 써도 된다.
14. 쓸 수 있는 기호: ² ³ √ ± × ÷ ≤ ≥ ≠ ≈ ∞ ∑ ∫ π α β γ θ → ← ↑ ↓ ( ) [ ] < > = + - / . , : ;
15. 쓰지 않는 것: 이모지, 한자, 마크다운(**, #, 표, 목록 기호), 세로선 표, 전각 문자, 드문 한글 음절.
    표가 필요하면 줄로 풀어서 "항목: 값" 으로 쓴다.

[자체 점검]
16. 출력하기 전에 모든 줄을 위 폭으로 계산해서 128픽셀을 넘는 줄, 6줄 넘는 페이지, 9쪽 넘는 파일,
    번호 중복, 존재하지 않는 링크가 없는지 확인한다. 위반이 있으면 고쳐서 출력한다.
17. 사용자가 tools/check_notes.py 의 출력(E/W 줄)을 붙여 주면, 그 줄에 적힌 파일·쪽·줄만 정확히 고쳐서
    해당 파일 전체를 다시 출력한다. 다른 내용은 바꾸지 않는다.

[우선순위]
18. 출제 빈도·중요도가 높은 것부터 앞 번호. 시험장에서 가장 먼저 찾을 항목이 01번.
```

## 요청 1: 구조부터 확정

```
첨부한 자료 전체를 보고, 시험장에서 찾아볼 노트의 폴더·파일 목록만 먼저 제안해줘.
- 폴더 = 과목/단원, 파일 = 한 가지 주제(공식 묶음, 개념 정리 등). 파일당 9페이지 이하.
- 폴더와 파일에 두 자리 번호를 붙이고, 각 파일에 예상 페이지 수와 한 줄 설명
- 출제 빈도·중요도 순으로 번호를 붙여줘
- 파일명에는 문제 지문에서 가장 먼저 눈에 띄는 표현을 넣어줘
- 폴더 00 은 색인용으로 비워 두고, 내용 폴더는 01 부터
내용은 아직 쓰지 마.
```

## 요청 2: 폴더 단위로 내용 생성

```
확정한 목록 중 [01_폴더명] 폴더의 파일을 전부 지침 규칙대로 만들어줘.
출력 후에 줄 폭(128픽셀), 페이지당 6줄, 파일당 9쪽, 링크 번호를 스스로 점검해서
위반한 곳은 고쳐서 다시 보여줘.
```

한 번에 한 폴더씩 시키세요. 전체를 한꺼번에 시키면 뒤쪽이 부실해지고 규칙 위반이 늘어납니다.

## 요청 3: 색인 생성 (모든 폴더가 끝난 뒤)

```
지금까지 만든 모든 파일의 "이럴때:" 키워드를 모아 notes/00_색인/ 을 만들어줘.
가나다순, 한 줄에 "키워드,키워드 →폴더번호/파일번호" (필요하면 :쪽), 링크 번호는 실제 파일 번호와 일치해야 해.
한 페이지는 6줄 이내, 한 줄은 122픽셀 이내로 맞춰서 여러 페이지로 나눠줘.
```

## 요청 4: 검사 결과로 수정

```
tools/check_notes.py 를 실행한 결과야. E 로 시작하는 줄을 전부 고쳐줘.
아래 파일들만 전체를 다시 출력해줘. 다른 내용은 바꾸지 마.

(여기에 check_notes.py 출력 붙여넣기)
```

## 참고: check_notes.py 가 보는 것

| 구분 | 내용 |
|---|---|
| 오류(E) | 한 줄 128픽셀 초과(링크가 있는 쪽은 122픽셀), 페이지 6줄 초과, 파일 9쪽 초과, 폰트에 없는 글자, 번호 중복, 없는 링크 대상(폴더/파일/쪽), 페이지당 링크 8개 초과 |
