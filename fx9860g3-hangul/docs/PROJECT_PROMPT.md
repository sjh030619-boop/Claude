# 시험 노트 프로젝트용 통합 프롬프트

Claude 프로젝트에 **프로젝트 파일로 `check_bundle.zip`(이 폴더에 있음)과 시험 자료**를 올리고,
아래 코드블록을 **그대로 한 번에** 붙여 넣는다. `[ ]` 안만 채운다.

```
[과목명] 시험 대비 계산기 노트를 만들 거야. 자료는 프로젝트 파일에 있어.
시험: [날짜] / 범위: [단원] / 유형: [서술형·계산·객관식 비율] / 계산기: CASIO fx-9860G III (화면 128×64 px)
프로젝트 파일 check_bundle.zip 은 노트 검사기야. 납품 전에 반드시 돌려 (아래 "자체 점검").

■ 진행 순서
1단계 구조 제안 → 내가 확정 → 2단계 본문 → 3단계 색인 → 납품(zip).
한 단계씩만 진행하고, 내가 확정하기 전에는 다음 단계로 넘어가지 마.
본문이 많으면 폴더 몇 개씩 나눠서 납품해도 돼. 단, 확정한 폴더·파일 번호와 링크는 그대로 유지해.

■ 1단계: 구조 제안 (본문은 아직 쓰지 마)
1. 족보와 강의자료를 전부 읽고 출제 경향을 분석해. 자주 나오는 문제 유형, 새 시험에서 소재만 바뀌어도
   그대로 쓸 수 있는 것, 그림이나 숫자에 의존해서 풀이 방법만 줄 수 있는 것을 구분해서 알려줘.
2. 폴더와 파일 목록만 제안해.
   - 폴더 = 주제 묶음, 파일 = 한 가지 문제 유형. 폴더는 01부터 두 자리 번호, 00은 색인용으로 비워 둬.
   - 출제 빈도 순으로 번호를 붙여. 파일명에는 문제 지문에서 가장 먼저 눈에 띄는 표현을 써.
   - 각 파일에 예상 쪽수와 한 줄 설명을 붙여. 쪽수 상한은 없어.
3. 내가 확정하면 2단계로 넘어가. 확정한 번호는 이후 바꾸지 마. 추가는 뒤 번호로 해.

■ 2단계: 본문 작성 원칙
[내용]
- 새 시험지를 봤을 때 바로 쓸 수 있어야 해. 연도, 문항 번호, 배점은 쓰지 마. 족보에만 나온 특정 소재
  (특정 제품이나 상황)에 묶인 풀이는 넣지 마. 필요하면 소재를 바꾼 일반 예제로 넣어.
- 서술형: 답안지에 그대로 옮겨 쓸 수 있는 완성 문장으로 써. 분량별로 짧은 답안, 보통 답안,
  긴 답안(분류/구조 + 항목 설명 + 사례)을 둬.
- 계산형: 문제를 보고 순서대로 따라 할 수 있는 풀이 절차(주어진 값 → 식 → 대입 → 결과 → 해석)와
  일반 예제 풀이, 자주 하는 실수를 넣어.
- 교재에 없는 내용은 줄 맨 앞에 "교재밖:" 을 붙여. 족보나 그림이 판독 불가능하면 추측하지 말고
  줄 맨 앞에 "불확실:" 을 붙여서 적어. (이 두 표식은 정확히 이 글자로 써.)

[이럴때와 연관]
- 각 파일의 첫 쪽에만 "이럴때:" 줄을 둬. 문제 문장에서 따온 짧은 표현 2~4개로 써 (예: 빈칸 채우기, 단점 논하라).
- 첫 쪽에 "연관:" 줄로 같이 쓰이는 파일을 링크해. 링크가 걸린 이유는 README.md에 표로 정리해.

[색인]
- 색인 폴더는 00 하나만 써도 되고, "00_객관식색인", "01_서술형색인" 처럼 이름에 "색인"이 들어간 폴더를 둘까지
  둘 수 있다 (계산기에서 첫째는 F2, 둘째는 F3 키). 폴더마다 하나의 문서로 이어 붙고 초성 목차가 따로 붙는다.
- 색인 폴더(00 또는 이름에 "색인")에는 문제에 나오는 표현을 가나다순(영문·숫자로 시작하는 표현은 맨 뒤)으로 넣고 파일:쪽으로
  연결해. 아주 세세하게 넣어. 한 줄에 "표현 →폴더/파일:쪽" 하나씩.
- 색인 쪽은 제목 1줄 + 항목 5줄이야. 제목은 아무거나 써도 돼. 빌드가 쪽 제목을 "색인 ㄱ 각~계"처럼
  자동으로 바꾸고, 맨 앞에 초성 목차를 자동으로 만들고, 색인 파일 여러 개를 하나로 이어 붙여.
  그래서 색인 파일은 몇 개로 나눠도 되고, 항목 정렬만 정확하면 돼.

■ 형식 규격 (fx-9860G III, 128x64 px)
- 파일마다 코드블록 하나, 바로 위 줄에 경로 (notes/NN_폴더/NN_파일.txt). 쪽은 --- 로 구분해.
- 텍스트는 BOM 없는 UTF-8, 줄바꿈 LF.
- 쪽당 6줄 이하. 1줄은 제목. 이럴때와 연관은 첫 쪽만. 마지막 줄은 선택으로 "주의:".
- 링크는 →폴더/파일:쪽 형식으로 쓰고 (예: →2/04, →7/03:2), 쪽당 8개 이하. 폴더 번호는 앞의 0 없이,
  파일 번호는 두 자리로 써.
- 링크 줄 모양: "제목 →폴더/파일:쪽" 처럼 한 줄에 링크 하나와 제목을 쓰면, 계산기에서는 줄 전체가 선택되고
  →폴더/파일:쪽 글자는 화면에 보이지 않아 (제목만 보임). 그래서 이 줄의 폭은 토큰을 뺀 제목 기준으로 잰다.
  "연관:", "함께:" 처럼 ':' 로 끝나는 레이블 줄이나 한 줄에 링크가 둘 이상인 줄은 토큰이 그대로 보이니
  토큰 폭까지 계산에 넣어.
- 한 줄은 128px 이하. 단, 링크(→)가 하나라도 있는 쪽은 모든 줄이 122px 이하야 (선택 표시 칸 때문).
  첫 쪽(이럴때/연관)과 색인 쪽이 여기에 해당해.
- 폴더명과 파일명은 14자 이하(번호 제외), 한글·영문·숫자·-·_ 만 써.
- 글자 폭: 한글, √→←↑↓≤≥≠∑∫∞παβγθ①~⑩❶~❿▽ = 8px, 원문자 ⑪~⑳ ⓐ~ⓩ Ⓐ~Ⓩ ㉠~㉭ = 10px, ㉮~㉻ = 12px, ≈ = 10px, 공백과 쉼표 = 3px, . = 2px, : = 4px,
  ( ) [ ] = 3px, + × ± ÷ = 6px, = 5px, < > - / ² ³ ; = 4px, 영문과 숫자 = 5px,
  ^{..} 와 _{..} 는 글자당 4px.
- 글자 위 모자·막대: ŷ ȳ Ŷ 처럼 유니코드 글자를 그대로 써 (예측값 ŷ). x̂ 처럼 x 뒤에 결합 문자 U+0302(모자),
  U+0304(막대)를 붙여도 돼. 폭은 기본 글자 하나와 같아 (결합 문자 폭 0). 위 두 가지만 지원해 (다른 악센트는 안 돼).
- 제곱근·시그마·벡터 (수식 줄 $...$ 안에서만): √{내용} (예: $σ=√{a^{2}+b^{2}}$, 내용은 글자와 첨자만, 분수 불가),
  ∑_{i=1}^{n} 처럼 ∑ 뒤에 _{아래}와 ^{위}를 붙이면 한계값이 ∑ 아래위에 쌓여 (한계는 영문·숫자·기호만),
  글자 뒤에 결합 문자 U+20D7 을 붙이면 화살표 v⃗ 가 돼. 분수 {분자;분모} 안에는 √ 와 ∑ 한계를 넣을 수 없어.
  폭: √{..} = 7 + 내용 폭, ∑ 한계 = max(∑ 폭, 한계 글자 수 × 4) + 1.
- 절댓값은 |x| 처럼 세로줄을 써도 돼 (| 는 이제 금지 문자가 아님). 분수·제곱근·∑ 한계가 들어간 식을 |...| 로 감싸면
  수식 줄($...$ 안)에서 세로줄이 22px 높이로 길게 그려져. 세로줄 하나는 폭 3px. 단순한 식 |x| 는 보통 글자 크기.
- 표: 답안이나 문제 조건에 표가 있으면 표 줄로 써. 한 행을 한 줄로 쓰고 칸은 │ (U+2502, 상자 세로선)로 나눠
  (예: 구분│L1│L2). 연속된 줄이 하나의 표가 되고 계산기가 테두리와 칸 선을 그려 줘. 행 높이 11px (표 아래 1px 더):
  쪽 높이 = 일반 줄×10 + 수식 줄×22 + 표 행×11 + 표 개수×1 이 64px 이하야 (제목 1줄 + 표 4행, 또는 표 5행까지).
  폭 = 열별 가장 넓은 칸의 폭 합 + 열 수×3 + 1 이 128px 이하 (링크가 있는 쪽은 122px). 열은 3~4개 권장 (최대 6).
  칸 글자는 짧은 단어·숫자 위주로, 줄바꿈이 없으니 긴 문장은 넣지 마. 표 줄에는 수식($)과 링크를 못 넣어.
  큰 표는 쪽을 나눠 (표 제목 줄 반복) 쓰거나 "항목: 값" 줄로 풀어 써.
- 그림: 문제에 제시된 그림(도식, 그래프, 회로, 공정도 등)은 계산기 화면에 흑백 그림으로 넣을 수 있어. 그림 파일은
  notes/figures/이름.png (흑백, 폭 128px 이하, 링크가 있는 쪽은 122px 이하, 높이 64px 이하; 제목 줄 10px 과 같이 쓰면
  그림 높이 54px 이하) 로 만들고, 노트에는 [그림 이름] 한 줄(그 줄에 다른 글자 금지)을 써. 쪽 높이 = 일반 줄×10 +
  수식 줄×22 + 표 행×11 + 그림 높이 가 64px 이하여야 해. 그림 변환은 번들의 fig_tool.py (예: python3 fig_tool.py
  원본.jpg notes/figures/이름.png)를 쓰고, 파이썬(Pillow)으로 직접 그려도 돼 (선 굵기 1px 이상, 글자는 7px 보다
  작게 넣지 마; 라벨은 그림 아래 글로 써). zip 에는 notes/figures/ 도 같이 넣어.
  제시 그림이 있는 문제는: ① 그림 쪽 (제목 + 그림 + 한 줄 설명), ② 그림에 따른 답 쪽 (읽는 법, 풀이 절차, 답), ③ 그림이
  바뀌어도 쓸 수 있는 변형 쪽 (그림 모양별 답: 표나 "그림이 이렇게 보이면 → 이렇게 답한다" 줄)을 같은 파일에 이어 써.
  그림만 보여 주고 답은 다음 쪽에 두어 문제 풀이 중에 답이 먼저 보이지 않게 해.
- 수식 줄: 분수나 로그를 크게 보여야 하는 식은 줄 안에 $...$ 로 쓴다 (그 줄은 22px, 두 줄 높이를 차지).
  분수는 {분자;분모} (예: $p_{k}={e^{zk};∑e^{zj}}$, $={p-y;p(1-p)}$), 로그의 밑은 log_{2} 처럼 쓴다.
  분수 중첩 불가, 첨자 중괄호 중첩 불가 (e^{zk} 는 되고 e^{z_{k}} 는 안 됨), 수식 줄에 링크 불가.
  쪽 높이 = 일반 줄 × 10px + 수식 줄 × 22px 가 64px 이하여야 한다 (수식 줄 2개면 일반 줄은 2개까지).
  폭: 분수는 분자와 분모 중 넓은 쪽 + 4px, 분수 밖 첨자는 글자 폭 그대로 (분수 안 첨자만 4px/글자).
  식이 한 줄 폭(128px)을 넘으면 분수를 여러 줄로 나눠 써.
- 쓰지 않는 문자: 이모지, 한자, 마크다운, 표, 전각 문자, & # ? ~ " ' · % * ! \ ∏ Π ∥ Ø Σ,
  로마숫자(Ⅱ 등).
  예: %는 "퍼센트", 올림은 "올림(...)", 곱 기호는 ×로 써.

■ 자체 점검 (납품 전 필수)
- check_bundle.zip 을 풀고, 노트를 work/notes/ 에 만든 뒤 work/set.json 을 두고 실행해:
    python3 check_notes.py --dir work/notes
- 출력의 E 가 0개일 때만 납품해. W 도 가능하면 없애. 코드를 실행할 수 없으면 글자 폭을 직접 계산해서
  점검하고, 요약에 "체커 미실행"이라고 적어.

■ 납품
- 파일은 python zipfile 로 묶은 zip 하나로 보내고 (한글 파일명이 깨지지 않게), 이름은 notes-v1.zip,
  notes-v2.zip 처럼 번호를 올려. zip 루트에는 이것만 둬:
    notes/ (폴더들)   README.md   set.json   (수정본이면 CHANGES.txt 도)
  set.json 은 {"name": "영문8자이하 앱 이름", "title": "[과목명]"}.
- 요약은 짧게: 폴더·파일 수, 총 쪽수, 체커 결과(E/W 개수, 불확실·교재밖 줄 수), 특이사항.
  코드블록으로 본문을 보여줄 필요는 없어.

■ 수정 요청 처리
- 내가 체커의 E/W 줄을 붙여주면 그 줄이 가리키는 파일만 고쳐서, notes/ 경로를 그대로 둔 수정 zip
  (notes-v{N+1}.zip, 바뀐 파일만)으로 줘. 다른 내용은 바꾸지 마.
- 파일을 지우거나 이름을 바꾸면 CHANGES.txt 에 적어. 번호를 바꿔야 하면 먼저 나한테 물어봐
  (링크가 전부 틀어져).
```
